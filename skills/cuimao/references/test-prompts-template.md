# 诱饵测试题模板

第 6 步产出 `技能包/测试题.md`，按本模板填充。

**这个文件要留给用户，不是跑完就丢。** 用户以后改了任何一条 description，可以拿原题重跑一遍验证，不用重新造题。

## 怎么用这份题

派一个新的子 Agent 当测试员，**只给它所有技能的名称和 description，不给正文，也不给候选文件路径**。

盲测是关键。测试员如果看过正文，就会根据正文而不是 description 来判断，测出来的结果没有意义。

让它对每道题回答：该触发哪个技能，或者都不该触发。

## 第一层 · 同源混淆

技能总数只有 1 到 2 个时跳过这一层。3 个以上时，每个技能至少 2 道。

场景是"应该触发同一批技能里的另一个"。同一份内容拆出来的技能天然主题相近，部署后最常见的故障就是互相抢调用，而只测"完全无关的场景"根本发现不了。

## 第二层 · 宿主混淆

每个技能至少 2 道。场景是"应该由助手已有的通用能力处理，这批技能都不该触发"。

用户的助手里本来就装着几十个通用技能。新装进去的技能如果去抢这些活，会严重干扰他的日常使用。

参考题面：

- 帮我把这个表格里的数据算一下
- 帮我写一封邮件
- 帮我总结一下这个网页
- 帮我做个 PPT
- 帮我把这个文件夹里的文件整理一下

## 修复记录

答错的题，说明对应技能的 description 边界写得不清楚。改写该技能的 description，然后**重测全部题目，不是只重测答错的那几道**——改一个技能的边界会连带影响其他技能的判定，只补测局部会漏掉新引入的冲突。

最多两轮。

| 轮次 | 改了哪个技能 | 改了什么 | 本轮通过率 |
